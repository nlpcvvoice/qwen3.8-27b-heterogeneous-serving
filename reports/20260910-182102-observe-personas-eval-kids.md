# 三件新鲜事 — 记账本 📒 / 台词本 📖 / 考试卷 📝(给小朋友的图解)

> 说明:这是三个不同的想法,先记住三个字: **看、练、考**。

---

## 背景:机器人小店 🏪

```
路上有一家"机器人小店",专门帮人类回答问题。
店员有两个:
   🐘  TPU 哥哥 (又快又聪明, 一次能照顾 4 位客人, 上限 9 小时)
   🖥️  GPU 姐姐 (朴实可靠, 一次照顾 4 位客人, 上限 30 小时)
小店已经开张,人类会来排队问问题。
```

现在问题来了:小店虽然能营业,可 **老板不知道**:

| 老板想知道 | 的话 | 现在的情况 |
|---|---|---|
| 谁是客人?问得多不多? | 「今天来了多少人?」 | 🟡 只能说"来过" |
| 回答得好不好? | 「答得对不对?」 | 🟡 只验过几次 |
| 有没有浪费钱? | 「水电费怎么省的?」 | 🔴 完全不知道 |

后面的三件事,就是为了回答这三个问题。

---

## 第一件:「记账本」📒 — 可观测 Langfuse / MLflow

### 什么是"可观测"?

- 现在小店只有 **门铃** 🔔:客人一来,ntfy 门铃"叮咚"一声(我们能看到"来客人了""店员说好了")
- 但门铃只告诉老板**发生没发生**,不告诉:  谁?几点?问了什么?答多久?花了多少力气?

### 记账本要记什么?

```
┌─────────────────────────────────────────────┐
│   客人的每句话(输入的每个字)                    │
│   → 哪位店员接的?                              │
│   → 等了几秒才开始说?(TTFT)                    │
│   → 说了几个字?(token 数)                      │
│   → 花了多久?                                  │
│   → 客人后来"点赞还是差评"?(事后打分)            │
└─────────────────────────────────────────────┘
            全都写进一本大账本
```

### 两本账本怎么选?

| | MLflow 🖊️ | Langfuse 🌿 |
|---|---|---|
| 它是什么 | 通用"实验室笔记本" | 专门给"聊天机器人小店"的账本 |
| 爱记 | 模型训练、指标、参数 | 客人对话全程 + 花费 + 打分 |
| 适合我们吗 | 也适合 | 更对口 ✅ |

> 总之:门铃(ntfy)告诉我们"发生过",账本(Langfuse/MLflow)告诉我们"**好还是不好、花多少时间、要不要改进**"。
> 现状:门铃已经装好 ✅;账本**还没开簿** 🔴。

## 第二件:「台词本」📖 — personas(LangGraph 离线生成)

### 先讲一个拍电影的故事 🎬

导演想拍电影,可是没有演员。怎么办?
导演先把**各种"真实顾客"的台词**写出来:

```
  👩‍🏫 化学老师   → "帮我解释一下什么是化学平衡"
  👨‍💻 程序员     → "这段 Python 代码哪里错了?"
  🧒 小学生     → "鲸鱼为什么不是鱼?"
  👵 老奶奶     → "我忘记怎么用手机交电费了"
  📊 销售经理   → "把上季度报表总结成 3 句话"
  ...
                (一共几百个,什么样的人都请来)
```

这本"台词本"就叫 **personas(假顾客人设)**。
它用 **LangGraph(一个"导演机器人")** 在**后台离线**慢慢写出来,不用惊动 TPU/GPU 哥哥姐姐们。

### 离线生成有什么用?(关键好处 ✨)

```
营业时间外面 20 个顾客排队?    → 不行,太挤、太慢
用台词本假装 20 个人同时来?   → 可以!
```

- 用台词本去做"**假装的顾客大军**",一次冲进小店测生意(就是压测 Locust)
- 这些词句是**真实人类问问题的方式**,不是随便乱打字 → 测试才像真的

> 现状:连台词本都还没有 🔴;写好之后,压测才显得真实。

## 第三件:「考试卷」📝 — 评测体系补强(探针/断言/工具调用解析)

### 考试分三步

```
 ① 出卷子(探针 probe)     ② 判对错(断言 assert)     ③ 抓特殊答案(工具调用 parser)
```

| 步骤 | 机器人的叫法 | 用人话说 | 现状 |
|---|---|---|---|
| ① 出卷子 | **探针** (probe_tpu_kernel.py) | 每次开店前,拿几道固定题问店员(测速度+对错),比如 benchmark 126 字/秒 | 🟡 已有一份小卷子 |
| ② 判对错 | **断言** (assert) | 检查答案:必须"是数字就真的是数字""是 JSON 就得是 JSON""答案格式要对" | 🟡 有几道,不够全 |
| ③ 抓特殊答案 | **工具调用解析** (qwen3_coder parser) | 店员有时会"打个电话求助"(调用工具),比如"我要查天气:城市=北京"。parser 把这句话**抓住拆开**,检查电话打对没有 | 🟡 只写过一份 |

```
        例子:店员答「我要打开日历工具,参数:明天 9 点」
        parser 把它拆出来 →
            工具名 = 日历 ✅
            参数   = 明天 9 点 ✅
        这就是 "会打电话的机器人" 的专项检查 🔍
```

### 考完试呢?还可以上"AI 评委" 🧑⚖️

- 有的题没有标准答案(比如"这段话说得漂不漂亮")
- 那就请**另一个 AI 当评委**(LLM-as-judge)来打分
- 再进一步:把几份答案并排比(bf16 全精度 vs 4bit 压缩)看谁更好

> 现状:探针有 ✅ / 断言和解析器 🟡 / AI 评委 🔴。
> 目标是:每次新店员来(每次新内核),都自动做一遍"考试",有张成绩单存档。

---

## 三件大事放一起看 🗺️

```
     生成台词本(7 personas)            →    线下,不占配额 ✅
        └──▶ 用台词本做压测(Locust)     →    需要店员在线 🔴
     记账本(6 可观测)                   →    让每一次回答都被记录
        └──▶ 从账本里捞出成绩(延迟/字数/花费)
     考试卷(8 评测)                     →    出卷→判对错→查电话→AI评委
        └──▶ 每回给店员写一张成绩单
```

## 三个问题,三件东西,三个状态 ✅

| 老板的担心 | 解决工具 | 现在状态 |
|---|---|---|
| 不知道客人怎么来、怎么答 | 记账本 (Langfuse/MLflow) | 🔴 没开簿 |
| 压测不像真人问问题 | 台词本 (personas + LangGraph) | 🔴 没台词本 |
| 答得对不对、是否会打电话求助 | 考试卷 (探针/断言/工具调用 parser) | 🟡 已能考,还不全 |
