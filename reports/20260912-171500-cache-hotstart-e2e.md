## 2 · 三个根因级问题

### A. 推送了错误的内核源文件

| 项 | 详情 |
|---|---|
| 问题 | v14→v16 使用 `kaggle-tpu-lab/kernel/serve_qwen38_gpu.py`(旧单文件复制逻辑),tar 修复只在 `p3/kernel/` |
| 根因 | `app/push_gpu_serve.py` KERNEL_SRC 指向 `kaggle-tpu-lab/` 路径 |
| 现象 | 发布 `engine-cached path=/kaggle/working/llama-server size=0GB`,下载仅 17KB |
| 修复 | `cp p3/kernel/... kaggle-tpu-lab/kernel/...` 同步 + commit |

### B. 17KB "llama-server" 是启动器 stub

| 项 | 详情 |
|---|---|
| 问题 | llama.cpp ≥v0.7x 拆分 `bin/llama-server` 为 17KB stub + `bin/llama_server` 真身 |
| 旧代码 | `shutil.copy2(LLAMA_SERVER, dst)` 只复制了 stub |
| tar 方案 | `package_engine()` 打包 `bin/` + `lib/` 所有成员(含 13 个 .so + llama-server) |
| 结果 | tar 大小 50.4MB / 23 成员,内含 `libllama-server-impl.so` |

### C. Kaggle 数据集上传自动解压 `.tar.gz`

| 项 | 详情 |
|---|---|
| 问题 | `datasets create/version` 遇到 `.tar.gz` 后缀时服务器解包为目录,symlink 变 0 字节文件 |
| 现象 | 上传 48MB tar → 数据集内出现 `engine/bin/libggml-cuda.so 0` 等破损条目 |
| 验证 | 改名 `engine.bundle` 上传 → 完整 48MB 文件保留(服务器不识别后缀,不解包) |
| 结论 | 所有上传脚本输出后缀统一改为 `.bundle` |

## 3 · 远程停机机制

```
┌──────────────────┐  HTTP POST to ntfy.sh (Kaggle 内网可达)
│  qwen38-gpu-ctrl │ ──────────────────────────────────────────►  ntfy topic
│  (CPU/免费/秒启)  │     JSON: {"phase":"CONTROL","cmd":"stop"}     │
└──────────────────┘                                              │
                                                                  ▼
                                                          qwen38-gpu-serve
                                                          (GPU kernel)
                                                          控制线程收到 → os._exit(0)
```

| 特性 | 详情 |
|---|---|
| 触发时机 | 用 `app/push_stopper.py` 推送, ~2-4 分钟内生效 |
| GPU 消耗 | 0(CPU 免费档,不计入 T4 配额) |
| 成功率 | 3/3 (v14、v15、v17 均成功停止) |
| 核心原理 | Kaggle 内网可达 ntfy.sh,本机 GCP 不可达 → 用 Kaggle 脚本中转 |

## 4 · 缓存数据流

### 上传流程 (build_cache_stage)

```
本地 engine.tar.gz (50.4MB)
  → build_cache_stage 复制为 stage/engine.bundle + stage/manifest.json (sha256)
  → kaggle datasets version -p stage --dir-mode zip
  → 数据集: tentenshishi/llama-server-qwen38-cache (私有)
    内容: engine.bundle (50,359,000B) + manifest.json (155B)
```

### 内核 cache-hit 路径

```
find_input("llama-server-qwen38-cache/engine.bundle")  → 命中(>20MB)
  → unpack_engine(tar_path)  → BUILD/bin/llama-server + BUILD/lib/*.so
  → LD_LIBRARY_PATH = BUILD/bin:BUILD/lib
  → 发布 PHASE engine-cache-hit → 跳过 ~25min cmake 编译
```

### fetch_cache 往返验证

| 检查点 | 结果 |
|---|---|
| 数据集下载 | engine.tar.gz 50,359,000 bytes |
| bin/llama-server | ✅ 存在 |
| lib 运行时库 | 13 个 (.so + .so.0 + .so.0.x) |
| sha256 与 manifest 一致 | `29120d0169ab7dd32b8850892e4886319eae70bd16e7206524189a7ba05c6569` ✅ |
